## 1. Vector sets and test programs: inventory and dispositions
Disposition key: **commit** (every byte in the file is explicitly permissive and listed in `tests/fixtures/manifest.txt`), **build-ci** (built in CI from pinned source, digests committed in `tests/built/expected.txt`), **fetch** (scripted fetch at a pin, SHA-256 checked, never committed, never uploaded as an artifact), **local** (owner's machine only, `library` preset), **binary-oracle** (the program's result layout is learned by running it, not by reading its source), **rejected** [CF.14][CF.16]. Every licence, pin and hardware number below is taken from PSXDEV-EXTRACTS [CF.20]; sizes and release assets were read through the GitHub API [CF.24].

**1.1 Compact vector form and the comparison.** `tests/vectors/r3000/sst-sample.bin`, little-endian, written by `tools/sst2bin.py` (run with `python3 -I`) from the `.json.bin` at the pin (no JSON step needed: the upstream binary layout is documented in `transcode_json.py`, PX.41). Header: magic `SWR3`, u16 version, 12 ASCII bytes of the source commit, u16 file count; per file: 12-byte name, u16 case count; per case: u32 opcode, u32 address; initial and final state each as 32 × u32 R, u32 hi, lo, EPC, TAR, CAUSE, PC, i32 load target, u32 load value, u8 branch slot, u8 branch take, u32 branch target; u8 cycle count then {u8 actions, u8 size, u32 addr, u32 value} per cycle. About 420 bytes per case, so the 5,500-case sample is about 2.3 MB (derived) [CF.25]. The runner loads the state into the CPU with the load-delay and branch-delay latches set as given, executes one instruction with the bus-sample hook on, then compares every register, hi/lo, EPC/TAR/CAUSE, PC, both delay latches and each cycle's action, size, address and value. R0 is asserted zero in both states (the upstream transcoder warns when it is not). Exceptions cannot be exercised here (upstream disabled them), so `tests/cpu/exception_tests.c` covers them (1.1a). No permitted-difference list exists at the start; a documented upstream inaccuracy becomes a dated line in `tests/vectors/r3000/allow.txt` naming the upstream issue, never a silent skip [CF.17].
- **Recommendation:** first 100 cases per file; full set nightly. **Strongest alternative:** every tenth case (10× the sample). **Would change if:** the sample measures above 4 MB or the nightly finds a failure the sample missed twice in a milestone.

**1.1a What the vectors do not cover, and what does:**

| Gap in `r3000/v1` | Covered by | Expected from |
|---|---|---|
| Exceptions: address error, bus error, overflow, reserved instruction, cop unusable, interrupt, SYSCALL/BREAK entry with EPC/Cause/BD bit, BEV vector choice | `tests/cpu/exception_tests.c` and the `exc_matrix` fixture record | nugget `cop0`, `cop-branch`, `irq-branch-slot`, `sr-write` results (PX.25); psx-spx cpuspecifications |
| GTE | the 1150-case table (CF.02) plus `gte_vectors` fixture records; latency from nugget `gte-latency*` | PX.20, PX.22 |
| Load delay through LWL/LWR interlock, delayed-load cancel by a write to the same register | `tests/cpu/delay_tests.c` | PX.26, nugget `cpu` |
| I-cache, scratchpad, MMIO widths, access timing | `bus_*` fixture records; ps1-tests cpu/access-time and io-access-bitwidth logs | PX.31 |
| MULT/DIV cycle counts | `tests/cpu/timing_tests.c` | PX.13; nugget `mult-timing` probe output (recorded) |

**1.2 Reading a third-party program's result.** nugget tests are graded by their own positive success line on the TTY (never by the absence of a failure line, as upstream insists). ps1-tests GPU results are a VRAM compare against the upstream PNG quantised to RGB555, with the difference count reported and a per-test tolerance of 0 unless `allow.txt` names a documented hardware-variant difference. amidog's verdicts are screen text: the runner decodes VRAM rows with the learned glyph map and matches a tolerant regex; a correct core reproduces the hardware verdicts, and a disagreement between a program's own expectation and a cited hardware number is reported, not failed.

## 2. Self-authored fixtures (primary v1.0 evidence)
Pure armips assembly, MIT, committed as source under `tests/fixtures/src/`, assembled in CI by armips built with CMake from the commit tarball pinned by SHA-256 `f7a65102febb4811a336a06e6d93c7e84cc86548182d54e1b1b4e2bffe562f56` (230,419 bytes; commit `62adab4ef30d`) plus its two submodule trees by SHA (PX.50) [CF.07]. armips writes only the bytes between `.create` and `.close`, so every byte of a PS-EXE is ours; the 2048-byte header is emitted by `header.inc` with `.db`/`.dw` directives (magic `PS-X EXE`, `pc0`, `gp0`, `t_addr`, `t_size`, `s_addr`, `s_size`, region text) [CF.16 AP §2]. Disc fixtures are built by mkpsxiso v2.30 from the tag tarball pinned by `b44778180d239a586c13762322a1f4b9692c787db8772790ddd2fa255a75d9e0` (release zips are pinned too, PX.53, for legs that cannot build), with `date` on every entry and the identifiers stated, so eight legs produce one `.bin` digest [CF.08]. Sibling lessons: unclear-licence homebrew makes a poor gate; choose the fixture before the milestone starts [CF.17].

**`header.inc` (the 2048-byte PS-EXE header every fixture emits, fields as MAME's loader and rcheevos read them, PX.66):**

| Offset | Field | Fixture value |
|---|---|---|
| 00h | `PS-X EXE` | literal |
| 10h | `pc0` | 80010100h |
| 14h | `gp0` | 0 |
| 18h / 1Ch | `t_addr`, `t_size` | 80010000h, image size rounded to 2048 |
| 20h..2Fh | `d_addr`, `d_size`, `b_addr`, `b_size` | 0 |
| 30h / 34h | `s_addr`, `s_size` | 801FF000h, 1000h (the stub kernel sets `sp` from these) |
| 4Ch | region text | `Sony Computer Entertainment Inc. for North America area` for ntsc-u builds; the Europe and Japan strings for the other two profiles (strings as psx-spx documents them; they only tell a loader the region) |

**Byte identity across macOS, Linux and Windows.** Each leg builds armips and mkpsxiso from the checked tarballs (`cmake/Armips.cmake`, `cmake/Mkpsxiso.cmake`; wrong digest fails configure, `fixtures.tool_pin.self_test`), assembles every fixture, builds the discs, and writes each image's SHA-256 into `hashes.txt`; `hash-equality` requires the eight files to agree (ENGINEERING 4 [CF.18]). Rules: `.gitattributes` forces LF on `*.asm`, `*.inc`, `*.xml`; no `.incbin` of anything outside `tests/fixtures/src/`; `.sym` and `.map` files never hashed; the XA and CD-DA sources are generated by `tools/gen_audio.py` from a formula (sine sweeps), never recorded audio. **First fixture build (phase 2):** assemble `hello.exe` (header, mailbox, one `j $`) on all six legs, compare digests, and check the header against the runner's `--probe`.

| Fixture | What it proves | Why the oracle cannot be fooled |
|---|---|---|
| `hello.exe` | toolchain identity; loader honours `pc0`, `gp0`, `s_addr`; mailbox magic appears | digest only |
| `pad_counter.exe` | GP1 display on, a title screen (textured quad, own glyphs), a counter that increments on each Cross 0→1 edge read through SIO0 (JOY_DATA/JOY_CTRL hand-shake, digital pad id 5A41h), moves a sprite by 8 px and changes a SPU voice's pitch; counts edges only ("a control that changes play") | three measures differ between movie `none` and movie `press@60`: VRAM hash at frame 300, mailbox `presses`, audio transition hash; a core that draws nothing, ignores input or reports a held button as many presses fails one |
| `gpu_motion.exe` | double-buffered frames, GP0 polygons with Gouraud and texture, GP0(E3/E4) clipping, VRAM-to-VRAM copy, mask bit, 24-bit display; a rotating object so successive frames differ | per-frame VRAM hashes at 60/120/180 must be distinct and match pinned values; a static or wrongly-timed frame fails |
| `spu_tone.exe` | SPU RAM upload by DMA4 and by IO, a 4-bit ADPCM block table generated in assembly, key-on of two voices at known pitches, ADSR, main volume, reverb off | the runner's PCM transition hash and a per-voice ENVX record; the unit test derives the expected PCM from the same block table without the CPU (two paths to one hash) |
| `gte_vectors.exe` | loads 64 records of {registers, opcode} from its own table, executes, writes outputs to the mailbox; records chosen from the 1150-case table's opcode classes plus flag-overflow corner cases | values judged by `expected.csv` rows sourced `hw` (PX.22); the vector runner is a separate path |
| `timers_lines.exe` | Timer0 on dotclock, Timer1 on hblank, Timer2 on sysclk/8; counts between vblank IRQs (I_STAT bit 0); line count 263/314 by profile; dot counts per line by horizontal mode | mailbox numbers judged per profile against PX.12 and PX.21 (`hw`/`doc` rows) |
| `exc_matrix.exe` | address error on LH/LW misalignment, overflow on ADD, reserved instruction, cop1 unusable, SYSCALL and BREAK EPC with and without BD, IRQ mask through SR; each handler stores Cause, EPC, BadVaddr into the mailbox | the stub kernel installs no handler of its own; the fixture's handler at 80000080h records; judged by `expected.csv` sourced `doc` |
| `memcard_roundtrip.exe` | at boot reads magic + counter from card frame 1 via SIO0 (card id 5A5Dh, read 52h and write 57h commands, checksum), branches visibly, writes counter+1; `save_generation` increments | fresh-process continuation (HOSTS continuation protocol [CF.21]): run 1 with no `.1.mcr` shows 1, run 2 shows 2; the two `frame@120` hashes differ and the second `.1.mcr` equals the first plus one |
| `disc_boot.bin/.cue` | OpenBIOS boots `SYSTEM.CNF` (`BOOT = cdrom:\SWAY.EXE;1`); the executable is `pad_counter` plus a CD section: ReadN of 16 sectors into RAM and a CRC-32 record, GetID/GetTN/GetTD records, XA track playback (ADPCM, 37.8 kHz stereo) with CD audio volume set, one CD-DA track played by `Play` | mailbox CRC of the sectors, TOC records, and the PCM transition hash of the XA segment judged by `expected.csv`; a core that fakes CD reads fails the CRC |

**Design rules.** (1) A counter only a new input edge changes; a fixture never copies an input level into a result. (2) No self-passing verdicts: the fixture measures and draws, `expected.csv` judges. (3) ≤ 64 KB of authored content per PS-EXE; disc images carry fill sectors and generated audio, built in CI, never committed, excluded from release archives. (4) Each fixture initialises every register it depends on (I_MASK, DPCR, DICR, SPUCNT, GP1 reset) except where power-on state is the test; keeps its stack inside its own `s_addr` region; never calls a kernel function in PS-EXE mode. (5) Own 8×8 glyphs only; no third-party font. (6) Every fixture has a frame cap after which the runner reports `hang`. (7) The mailbox is the first 256 bytes of the loaded image at `t_addr` (80010000h), so no BIOS, kernel or stack can touch it; `pc0` = `t_addr` + 100h.

## 3. Oracles, ledger and the local library
### 3.1 Oracles
Released binaries only; no copyleft or non-commercial source is opened [CF.16]. Agreement is a locator written to the ledger, never a gate.

| Oracle | Licence, binary | BIOS | Headless interface and what it emits | Tier |
|---|---|---|---|---|
| PCSX-Redux dev AppImage [CF.09] | GPL-2 (LICENSE); binary from the distrib.app dev channel pinned by build id and SHA-256 | **OpenBIOS** (ships inside the AppImage; or `-bios` our CI-built copy) | `-no-ui -run -stdout -testmode -interpreter -softgpu -bios X -loadexe F` (or `-iso`); exits with the test verdict in `-testmode`; the Lua API (docs) reads memory and registers and takes screenshots; under `xvfb-run` since SDL wants a display (nugget's `run-emulator.sh` pattern: one X server, per-job `HOME`) | nightly in CI: the only oracle that runs with **no Sony bytes** |
| DuckStation `duckstation-regtest` [CF.10] | CC BY-NC-ND 4.0 at `124a4b16feda` (facts and binaries only); `latest` rolling release ships AppImages, a macOS zip and Windows zips | a real BIOS (`PatchFastBoot` forced; no HLE) | `-dumpdir D -dumpinterval N -frames F -renderer Software -log Error -- game.cue|chd`: PNG frame dumps every N frames; Null audio backend (no audio dump); `scripts/run_regression_tests.py` and `check_regression_tests.py` compare dump trees | local only (BIOS) |
| Mednafen [CF.11] | GPL-2 (unverified: the release page states no licence line); binaries for Windows, source elsewhere | a real BIOS | no headless or frame-cap option in the documentation; `video.driver softfb`, `-sound 0`, `-qtrecord` (video+audio QuickTime, codecs raw/cscd/png), `-soundrecord` WAV; exit is a key binding | local, by hand |

| MAME `psu`/`psj`/`pse` [CF.13] | GPL-2 driver, BSD-3 devices (PX.38) | BIOS set required | `-quik file.exe` quickload; Lua as in the siblings | local |
| Real hardware | the owner's console, if one exists with a way to load executables (serial loader or modified console) | its own | §2 fixtures; photo or capture | arbitrates, asked for only with a reason |

**Per-frame comparison** (one record per frame at the vblank tick; alignment search k in [−2, 2] frames): RAM SHA-256 over the 2 MB minus the kernel area (0..FFFFh) and the stack page; VRAM hash of the displayed area quantised to RGB555 (24-bit frames to RGB888); GPU state (GP1 display fields, GPUSTAT); SPU voice state; frame number. PCSX-Redux gives RAM, VRAM and registers through Lua (docs); DuckStation gives PNGs only; Mednafen gives recordings only.

**When a locator disagrees.** (1) The nightly writes `oracle=<name>:agree@F` or `diverge@F` into the ledger row's evidence and updates the rolling `nightly` issue; nothing turns red. (2) The agent reproduces the first divergent frame with `--trace first-fault` (§4) and names the device. (3) It decides whose error it is from documents and farm results, never from the oracle's source: a nugget RESULTS.md or ps1-tests log outranks the oracle; a psx-spx number outranks an emulator; two oracles agreeing against us with no document is a hypothesis for a fixture record. (4) A fix lands with a fixture record or unit test, not a tuned constant.
- **Recommendation:** PCSX-Redux + OpenBIOS nightly on Linux x64 as the routine locator; DuckStation regtest, Mednafen and ares local. **Strongest alternative:** a libretro-host harness loading Beetle PSX or SwanStation from the libretro buildbot (both can use OpenBIOS per its COMPATIBILITY.md) for a second CI opinion. **Would change if:** the AppImage fails to run under Xvfb on ubuntu 26.04 twice, or PCSX-Redux's own GPU disagrees with ps1-tests PNGs on a case where we match hardware.

### 3.2 Compatibility ledger and ratchet
`tests/compat/ledger.csv`: one header line, comma-separated, no field may contain a comma, quote or newline (a schema test enforces it).

| Column | Meaning |
|---|---|
| `id` | the Redump serial (`SLUS-00067` form, from SYSTEM.CNF or the DAT) plus `/` plus the 32-hex rcheevos MD5 of the boot executable (PX.82, PX.86) [CF.22], computed by our own `--probe`; for own fixtures `fixture/<name>`; for built third-party programs `built/<name>` |
| `track1_sha1` | SHA-1 of track 1 as the Redump DAT lists it, when known; `-` otherwise (identifies the exact dump without naming it) |
| `title` | from the CC-BY-SA-4.0 libretro-database DAT with its notice in `THIRD-PARTY-NOTICES.md` (PX.81); fixture names otherwise; `unlisted` when absent, and then no hash is written (§3.3) |
| `region` | `ntsc-u`, `ntsc-j`, `pal` (from the serial prefix and the PS-EXE region string) |
| `media` | `cue-bin`, `chd` (v2.0; a v1.0 run records such a disc as `unsupported`, exit 77), `exe`, `multi-disc:n` |
| `predicate` | `boots@F` (weak: display on, ≥ 2 distinct frames, CPU not stuck in an exception loop, no first fault), `frame@F=H`, `ram@F:$ADDR=VV`, `mailbox@F`, `audio@F=H`; prefix `movie:<file>/` for scripted input |
| `status` | `pass`, `fail`, `unknown` (seed rows), `unsupported` (names the missing device: multitap, lightgun, PocketStation, link cable; exit 77), `skipped` (with a reason; never in CI tiers), `infrastructure_error` (harness or oracle broke; neither pass nor fail) |
| `evidence` | 16-hex hash prefix, mailbox CRC, or run URL, plus the core commit (12 hex) |
| `date` | ISO date of the last evaluation |

Three example rows (hash values are placeholders until phase 3 pins them):
```
id,track1_sha1,title,region,media,predicate,status,evidence,date
fixture/pad_counter,-,pad_counter.exe,ntsc-u,exe,movie:press60/frame@300=0000000000000000,unknown,-,2026-10-19
built/nugget-gte,-,nugget tests gte,any,exe,tty:Synthesis: SUCCESS,unknown,-,2026-10-19
SLUS-00000/00000000000000000000000000000000,<40-hex>,<title from the DAT>,ntsc-u,cue-bin,boots@1800,unknown,-,2026-10-19
```
- **Ratchet:** key = (`id`, `predicate`). Allowed transitions: `unknown` → anything, `fail` → `pass`, `pass` → `pass`. `pass` → anything else, or a changed hash on a passing `frame@`/`audio@` row, needs a dated line in `tests/compat/allow.txt` (`YYYY-MM-DD <id> <predicate> <reason> behaviour-rev=<n> expires=YYYY-MM-DD`) that names the behaviour-revision bump and expires within 60 days. CI fails when fresh results and the ledger disagree in either direction. **Protected baseline:** the ratchet job first checks out `github.event.pull_request.base.sha`, copies the ledger and `scripts/compat-ratchet.sh` to `$RUNNER_TEMP`, then checks out the PR, so a PR cannot loosen its own judge [CF.14]. Tier is not a column: rows whose id is in the manifest or `tests/built/expected.txt` run in CI; every other row is local. `docs/compatibility.md` is generated from the CSV (counts by status × region × media, then one row per title) and `policy.compat_doc_fresh` regenerates and compares.
- **Recommendation:** the ten-column CSV with a generated doc. **Strongest alternative:** nesturbator's sorted TSV [CF.15]. **Would change if:** a DAT title keeps a comma (then TSV) or a dashboard consumer appears (emit JUnit too).

### 3.3 The local `library` preset
`scripts/library.sh` loads git-ignored `.env.local` (`SCHWAYSTATION_DISC_DIR`, `SCHWAYSTATION_BIOS_DIR`), runs `cmake --workflow --preset library`; configure fails if a directory is missing (no self-skip). It parses each `.cue` through the core's own reader (`.chd` joins in v2.0 with libchdr, BSD-3, PX.85; until then a `.chd` is counted as unsupported, never as unlisted), computes the serial and the rcheevos MD5 [CF.22][CF.23], looks the serial up in the build-time table from the libretro-database DAT, registers `library.<serial>` only for matches, and writes `build/library/results.csv`; `scripts/compat-update.sh` merges it into the ledger. What leaves the machine: the serial, the MD5 and track SHA-1 (both already public in RetroAchievements and Redump lists), the DAT title, the predicate result, the date. What never leaves: file names, paths, any hash of an unlisted file (counted, not named), frames, RAM, saves, BIOS digests other than the public ones already in ASSET_POLICY [CF.16]. `ci*` presets never define the directories or register library tests, so the exact inventory holds (ENGINEERING 3). The same preset is the only place DuckStation regtest, Mednafen, ares and MAME run.

## 4. First-fault diagnostics, trace format and TTY capture
A **first fault** is the earliest event the core classifies as impossible or unmodelled: an unmapped address, a reserved instruction, a cop unusable outside cop0/cop2, a GP0 command the GPU does not implement, a CD command the controller does not implement, a DMA sync mode on a channel that cannot use it, a write to a read-only register with side effects, or an exception loop (the same EPC taken 1000 times). The runner stops at the first fault with `--stop-on-fault` (default in CI) and prints one line, then a trace tail; the classes and the record fields are the ARCHITECTURE file's to refine [CF.19].

Trace record (`--trace first-fault` writes the last 4096 records, `--trace cpu` streams them), one line each, tab-separated: `frame`, `line`, `dot` (GPU position at the tick), `cycle` (33.8688 MHz count since reset), `pc`, `opcode` (hex and disassembly), `event` (`exec`, `rd`, `wr`, `irq`, `dma`, `gp0`, `gp1`, `cd`, `spu`, `fault`), `addr`, `width` (8/16/32), `device` (ram, scratch, bios, gpu, spu, cdrom, dma, timer, sio, irq, mdec, exp1, exp2), `value`, `note` (for `cd`: the command byte, parameter FIFO and the pending INT; for `gp0`: the command word and the words still owed; for `fault`: the class). The TTY stream is captured separately: every byte the fixture or kernel writes through the A(3Ch) putchar path or the stub-kernel port is appended to `tty.txt` with the frame number at each newline, which is also how nugget success lines and ps1-tests logs are read. `--mailbox` dumps the mailbox as `id=value` lines with the CRC check (§2). On a fault or hang the runner also writes the displayed VRAM area as PNG (own fixtures only in CI; never for library discs). Exit statuses are the runner's one X-macro table (HOSTS 4): 0 done, 1 failure (a predicate or a record outside its row), 2 usage, 3 hash mismatch, 4 save size, 5 state rejected, 6 fixture fault (status FFh), 7 first fault, 8 hang, 77 unsupported, 78 infrastructure error.
**The RAM mailbox.** The first 256 bytes of every own fixture image, at `t_addr` = 80010000h (rule 7 of §2); the runner reads it with `peek` at frame F, at status 00h, or at the frame cap (then `hang`):

| Offset | Content |
|---|---|
| 00h..03h | magic `SWMB` |
| 04h | protocol version 1 |
| 05h | status: 80h running, 81h waiting for input, 00h done, FFh fault (the fixture detected an impossible state) |
| 06h / 07h | record count / fixture id |
| 08h..0Bh | CRC-32 (IEEE, as the CD fixture uses for sectors) over 10h..FFh |
| 0Ch..0Fh | optional handler address the stub kernel jumps to on an exception (0 = none) |
| 10h + 8n | record n: test id u16, flags u16 (bit 0 valid, bit 1 timed out, bit 2 profile-dependent), value u32 LE; up to 30 records |

The `mailbox@F` predicate checks magic and CRC, prints `id=value` lines, and judges them against `tests/diag/expected.csv` (`fixture, test, profile, value or range, source hw|doc|farm|oracle|derived, citation`). On screen the fixture draws one row per record, `NN VVVVVVVV`, in its own 16 hex glyphs inside the 256×240 safe area, with the CRC in double-height digits so a photograph of a real console can be transcribed and checked by `schwaystation-run --mailbox-check session.csv`. Three example rows:
```
fixture,test,profile,expected,source,citation
timers_lines,lines_per_frame,ntsc-u,263,doc,PX.12
gte_vectors,rtps_case07_sxy2,*,<u32>,hw,PX.22
exc_matrix,lh_misaligned_cause,*,00000010,doc,PX.13
```
A row with source `farm` names the nugget RESULTS file and pin; `oracle` names the oracle and build id; `derived` names the preparation section. The runner exits 1 on any record outside its row and prints every record either way; a missing row is an `infrastructure_error`, never a pass [CF.17].

**Owner hardware-run protocol** (asked for only with a reason). (1) The agent prepares `tests/hw/<date>/` with the PS-EXEs, the disc `.bin/.cue` and a `session.csv` template; the owner loads them through whatever loader the console has (serial, a flash cart in the parallel port, or a burned disc on a console that accepts one). (2) Record once per session: model (SCPH-xxxx), region, video standard, loader, capture path. (3) Cold-boot each fixture twice; photograph or capture the screen; record line-out for audio fixtures. (4) Type the values into `session.csv`; the CRC check refuses a row set whose CRC differs from the photographed one. (5) Commit the CSV only; photos and recordings stay local. (6) Loaders may leave kernel state behind, so every fixture initialises what it does not measure.

- **Recommendation:** measurements in RAM and on screen, verdicts in `expected.csv`; the trace record above, written by one function so unit tests can assert its shape. **Strongest alternative:** a binary trace with a separate decoder. **Would change if:** the text trace costs more than 10 % frame rate while enabled (then binary with the same fields).

## 6. Fuzz targets
The v1.0 names are ENGINEERING 3's nine plus `sio` (ARCHITECTURE 13); `tests/fuzz/<target>.c` each with a libFuzzer entry and a replay `main` for the `fuzz.regress.*` seeds (committed, ≤ 4 KB each, generated by our tools, never from game bytes):

| Target | Input | Invariant |
|---|---|---|
| `cue` | cue sheet text | parser never reads past the buffer; rejects unknown track types; every FILE line resolves or fails cleanly |
| `exe` | PS-EXE header + body | loader rejects `t_addr`/`t_size` outside RAM, overlapping stack, zero `pc0`; no write outside the 2 MB |
| `cnf` | SYSTEM.CNF text | BOOT, TCB, EVENT, STACK parsed with bounds; path length capped |
| `memcard` | 128 KB image | directory-frame checksums validated; a corrupt card never indexes past frame 1023 |
| `state` | save-state blob | version and length checked before any field; a truncated state restores nothing |
| `chd` (v2.0, with libchdr) | CHD header + hunks | reader never returns more than one sector per call; hunk map bounds |
| `gpu` | GP0/GP1 word stream | every command consumes its documented word count; polygons with coordinates beyond ±1024 clip; no VRAM index past 1 MB |
| `cdrom` | CD command stream (command byte + parameter bytes + timing) | the state machine always reaches an INT or an error; parameter FIFO never overflows |
| `spu` | SPU register write stream | every write lands in the 512 KB; voice indices masked; reverb buffer base wraps |
| `mdec` | MDEC command words + bitstream | block decode never writes past the output buffer; run lengths bounded |
| `sio` | random bus bytes into the pad and card devices | command phase counters bounded; sector index masked; no reply longer than its table |

Rule: a target runs report-only until it has been green for 10 nightly runs; crashes found become `fuzz.regress.*` seeds in the same PR that fixes them [CF.17].

## 7. Admission rules for third-party fixtures
1. Judge the **bytes that end up in the executable or disc**: author code, the SDK runtime (`libpsn00b` is MPL-2.0; nugget's support runtime is MIT; libgcc carries the runtime exception), libcester (MIT), fonts, audio and data, generated bytes (headers, ISO structures are tool output). A tool's licence (armips MIT, mkpsxiso GPL-2, GCC GPL-3) does not reach its output unless the tool copies its own runtime in.
2. Licence evidence = LICENSE plus per-file headers **at the exact pin**; re-check at every pin bump. PCSX-Redux's GPL does not reach the nugget submodule (MIT), and that distinction is recorded in `THIRD-PARTY-NOTICES.md` with both URLs.
3. Disposition: **commit** only if every byte source is MIT, BSD, ISC, Zlib, Unlicense, CC0 or public domain, no Sony logo or licence string is embedded, and the notice is in `THIRD-PARTY-NOTICES.md`; **build-ci** or **fetch** for unstated, mixed, copyleft or non-commercial terms (digests only, no artifacts); **local** for commercial dumps, BIOS and anything not script-fetchable.
4. Firmware stays out: no Sony BIOS, no `licensea.dat` from PsyQ, no SCEx strings, even inside permissive repositories [CF.16]. OpenBIOS is admitted as third-party MIT code with its notice.
5. Size caps: a committed fixture source ≤ 64 KB; a committed vector file ≤ 4 MB; built discs ≤ 64 MB in the build directory and never committed.
6. Manifest row: `path<TAB>source<TAB>pin<TAB>licence<TAB>sha256<TAB>notice`; licence is an SPDX expression, `NOASSERTION` when unstated; build-ci rows live in `tests/built/expected.txt` with tool pins, source pins, image SHA-256 and predicate hashes.
7. Own fixtures: MIT source committed, bytes built, own glyphs, rebuilt and compared on every leg (§2).
8. **MPL-2.0 bytes (ps1-tests executables):** running a fetched binary needs no notice; redistributing it would. Fetch at the release tag by digest, never commit, never upload. The GTE table is transcoded from MIT source, so it is commit-clean.
9. **Fetched release zips** are admitted by digest only: the first fetch records the SHA-256 of the zip and of each file inside; a later fetch that differs is an `infrastructure_error`, and a pin bump is a PR.
- **Recommendation:** rules 1–9. **Strongest alternative:** admit by repository licence alone (would wrongly commit SDK bytes). **Would change if:** upstreams add per-file SPDX tags a script can check.
