# Phase 2 Plan 16: The own stub kernel Summary

**A 524-byte MIPS stub kernel, assembled by the pinned armips, committed as an array in the core and mapped at BFC00000h whenever the host gives no BIOS, pinned to its source by a drift test on every lane.**

- **Duration:** 5 min (from the first commit's ledger entry to the last task commit)
- **Started:** 2026-11-09T21:40:38Z
- **Completed:** 2026-11-09T21:47:00Z
- **Tasks:** 3
- **Files modified:** 12 (3 created, 9 modified)

## Accomplishments

- `stub.asm` is real MIPS: memory-control boot values, I_MASK and I_STAT cleared, a four-word jump at 80000080h, SR.BEV cleared after it, then gp, sp and a jump to pc0 from the launch block. The handler body sits in ROM, outside 80000000h-800000CFh, and records Cause, EPC, BadVaddr and SR at 80000210h before it checks the mailbox.
- Power-on points the BIOS window at `schway__stub_kernel_image` when the host has not mapped an image, so every host gets the stub with no extra call. A read or fetch past the 524 bytes is a bus error naming the BIOS and a first fault.
- `fixtures.stub.window` reads every word of the image through the bus; `fixtures.stub_drift` compares the assembled `stub.bin` with the array on every lane that builds fixtures. The stub's sha256 is `c567e5b40f21033e9e2739b2dbea1ea9a9275cd5eb70aa1d7dc986d96574f434`, one more `hashes.txt` line that hash-equality compares across the eight lanes.
- The reset and handler paths were executed once on the real CPU (scratch program, not committed): all six paths behaved as the truths say. Plan 02-17 adds the committed tests for the same paths.

**Stub image size:** 524 bytes (0x20C), sha256 `c567e5b40f21033e9e2739b2dbea1ea9a9275cd5eb70aa1d7dc986d96574f434`. The array file `src/stub_kernel.c` has sha256 `4a1ab9be5566468662e9c83b43686ebc1a179276b12b31e1f7b59687884cca53`. The plan's "about 2 KB" is an upper estimate; this image holds no kernel service yet (plan 02-18 adds the putchar entries).

**Layout of the image:** reset code at BFC00000h to BFC000EBh; FFh fill to BFC0017Fh; `j handler` at BFC00180h; handler body at BFC00188h; the shared spin loop at BFC001F4h; the vector jump template, copied to 80000080h, at BFC001FCh.

## Decisions Made

See `key-decisions`. In short: only k0 and k1 in the handler; the RAM vector is a four-word register jump because a KSEG0 `J` cannot reach the KSEG1 ROM; BEV is cleared without touching other SR bits; the unreachable gap before the BEV vector is FFh, not nops; regeneration reuses `tests/fixtures/tests.cmake` script mode, which is outside the gate-line count.

## Issues Encountered

- armips labels are case-insensitive: the label `launch` collided with the constant `LAUNCH`, fixed by naming the label `enter_image`.
- armips inserts no delay-slot or load-delay nops, so every load and branch delay in `stub.asm` is written out by hand and the assembled words were read back with `xxd` before the array was generated.
- `.rept` does not exist in this armips, so the gap before BFC00180h is one `.fill ..., 0xFF`.
