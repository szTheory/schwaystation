<evidence>
Plan 06-38 recorded one DMA1 start per pinned output guest. The trace shows 4-bit MADR 0x001FFEB8 at cycle 244776, BCR 0x20 at 244795, CHCR 0x01000200 at 244815, and CHCR clear at 458235. The 8-bit trace shows MADR 0x001FFE98 with the same BCR/CHCR sequence and clear at 522643. The digest-verified logs request buffers at 0x801FFE0C and 0x801FFDEC. Existing Plan38 diagnostics compare bytes using the requested log target; the relationship to the DMA1 start remains unresolved and must not be described as a DMA1 destination check.

The same guests have byte-for-byte identical DMA0 input, quantization table, scale table, and post-IDCT block. The pinned expected 4-bit bytes equal `min(15, (unsigned_8bit_pixel + 8) >> 4)` for all 64 corresponding pixels. The model's corrected 8-bit word literals from byte 40 onward now re-pack the pinned `psx.log` bytes, but this candidate was not tested after editing. Before Plan38's candidate changes, `mdec.guest_input`, `mdec.reference.4bit`, and `mdec.reference.8bit` failed with output mismatches. The ordered-status guest failed its unchanged cap with 82 status records, 82 input writes, zero output reads, and no Done marker. Keep all these selectors gating.
</evidence>
