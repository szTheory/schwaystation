## Fingerprint contract and comparable groups

At each exact run-head commit, `analyze_history.py` projected only workflow/build inputs. For a Release workflow it included both `release.yml` and the called `ci.yml`. The projection selected every workflow identity/route, all `CMakeLists.txt`, `CMakePresets.json`, `cmake/*.cmake` and `cmake/*.txt`, each CTest `tests.cmake` inventory and `tests/cmake/*.cmake`, `tests/fixtures/manifest.txt`, `pins.txt`, `scripts/*.sh`, and runner names/labels returned by that exact Actions attempt. It retained job commands, dependency edges, runner selections, matrices, toolchain/build setup, fixture/inventory entries, pins and actual runner labels.

Records were sorted bytewise by path and encoded as `path NUL normalized-content LF`, then hashed with SHA-256. Workflow YAML was parsed and key-sorted; only `name` and `timeout-minutes` fields were removed. JSON keys were sorted; CMake and shell comments were stripped without changing quoted/bracketed content; pin and fixture-manifest entries were sorted after blank/comment lines were removed. The route record contains workflow, event, main/non-main branch class and full versus fast-or-incomplete route. Product source files were excluded. PR events were excluded because Actions exposes the PR head, not the merge-ref revision used for execution; one reported PR head also lacked a local commit object. No nearby revision was substituted.
