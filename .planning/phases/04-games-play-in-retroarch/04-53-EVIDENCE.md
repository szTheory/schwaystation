# GPUSTAT field-status evidence and model decision

The checked C-shell's pinned `shell/gpu.c::waitVSync` polls opposite ODE/ODE2 combinations; the real trace never sees either bit set. This identifies a caller, not a hardware oracle. No black-frame or shell hash is accepted.

New primary evidence supersedes preparation's old bit-13 rule: PSX-SPX [status-register documentation](https://psx-spx.consoledev.net/dev/ps1/gpu/status-register/) and merged [PR 234](https://github.com/psx-spx/psx-spx.github.io/pull/234), public commit [519c8dbcc025467a6c80b02e61aafe3adcfa497b](https://github.com/psx-spx/psx-spx.github.io/commit/519c8dbcc025467a6c80b02e61aafe3adcfa497b), dated 2026-11-03, report v0/v2 hardware probes including PAL. `gh api repos/psx-spx/psx-spx.github.io/commits/519c8db --jq '{sha:.sha,url:.html_url,date:.commit.committer.date}'` exited 0; the PR API read also exited 0. Only documentation was consulted; no probe or emulator source from a prohibited project was opened.

The documented behavior distinguishes three events: bit 31 is suppressed outside displayed vertical lines; bit 13 changes on the last scanline, independently of the programmable vblank edge; disabling interlace retains bit 13. V0 exposes bit 13 as 0, while v2 reads 1 after GP1 reset. In 480i, the displayed part of the long/odd-drawing field has31=1/13=0 and the alternate field 31=0/13=1. Effective 240-line modes use scanline parity for 31, including IRS on with VDS off.

Decision: keep one saved boolean status phase. The coordinator confirmed that its earlier no-new-state expectation was conditional on existing state being sufficient. Retention after mode disable proves that a purely combinational current-mode/frame expression is insufficient. This field uses the already-approved unreleased v4 compatibility policy; no API/state/behavior 5 or owner approval is needed.

Under the existing fixed beam model, initialize the phase to 1 on full GPU reset; normal active-display interlace entry begins the documented initial partial-field phase 1. While IRS is enabled, toggle at entry into the model's final scanline; disabling IRS freezes the phase. V2 bit 13 exposes it and v0 forces the visible bit 0. Bit31 is 0 outside the programmed vertical display interval, inverse phase in 480i, or beam-line parity in effective240-line modes. Display disable and IRQ acknowledgements do not supply parity. GP1 command-buffer reset does not reset this phase.

Confidence boundary: the source reports alternating physical field lengths and an early-vblank mode-entry exception. The existing fixed 263/314-line, integer-clock beam is retained per D-06. Tests pin status semantics relative to that model and normal active-display mode entry; they do not claim exact new hardware timeline offsets, alternating line totals, missed-counter behavior or the exceptional early-vblank phase. The model uses phase 1 for mode entry deterministically without adding a timing rewrite. Public docs must say this. Future 48's actual independent GPUSTAT readiness log remains unchanged; its twelve cases cover readiness/DMA bits, not a hardware measurement of 13/31. No observed core output becomes captured expected data.
